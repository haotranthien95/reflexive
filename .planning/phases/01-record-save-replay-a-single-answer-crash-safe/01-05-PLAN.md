<objective>
Close verification Gap 2: the Baloo 2 typography locked by D-15 and the UI-SPEC does not exist in a release build. `google_fonts` fetches the family over HTTPS at runtime, nothing is bundled, and the `INTERNET` permission lives only in the debug and profile manifests — which are stripped from release. The shipped app silently falls back to Roboto and no developer would notice locally.

**User story (MVP mode):** **As a** learner reading a question at arm's length before speaking, **I want to** see the same friendly rounded typeface in the app I actually install as I see in development, **so that** the app I use is the app that was designed, and it looks right the first time I open it — including offline.

Purpose: the 01-02 SUMMARY flagged the runtime fetch honestly and even named this remediation; what it did not catch is that the release manifest makes the fetch impossible rather than merely optional. This plan takes the named remediation and adds the thing the phase never had — a check that proves the font loaded rather than silently fell back.

Output: `Baloo2-SemiBold.ttf` bundled as an asset with its licence, runtime fetching switched off, the release manifest deliberately untouched, and a test that fails loudly if the font ever stops loading.
</objective>

  <action>
    Create `test/theme/typography_test.dart`. Put `TestWidgetsFlutterBinding.ensureInitialized();` in a `setUpAll`. **Test order in this file is load-bearing** and must be exactly as listed below — the reasons are given per test and must be written into the file as comments so a later reorder does not silently defeat the checks.

    First test — the font genuinely loads. This is the check the phase has never had, and it must be the FIRST test in the file. Use a plain `test()`, not `testWidgets`, and no pump anywhere in it. Call `configureFonts()`, then in the SAME synchronous statement sequence call `GoogleFonts.baloo2(fontWeight: FontWeight.w600)` and immediately `await GoogleFonts.pendingFonts()` inside an expectation that it does not throw. Three properties of `google_fonts` 8.2.1 make this assertion real, and all three are also the reasons it is fragile if written any other way. (1) `loadFontIfNecessary` looks for a matching bundled asset first, and when none is found and `allowRuntimeFetching` is false it throws an exception naming the missing font, which is rethrown into the future `pendingFonts()` collects — so a clean completion is positive evidence the bundled face loaded, and a silent fallback cannot be mistaken for success. (2) `googleFontsTextStyle` adds that future to `pendingFontFutures` and REMOVES it on completion, so any `pump` between the `baloo2()` call and the `await` would let the future settle and leave `pendingFonts()` awaiting an empty list — a guaranteed pass regardless of outcome. There must be no `pump`, and no `await` of anything else, between the two. (3) `_loadedFonts` is a process-global set, so once any test in the run has loaded Baloo2 this call returns early and registers an already-complete future; that is why this test must run before any test that pumps `EnglishReflexApp` or otherwise resolves the family. Write all three reasons into the test as a comment.

    Second test — the asset is bundled. `final manifest = await AssetManifest.loadFromAssetBundle(rootBundle);` and assert that `manifest.listAssets()` contains at least one entry whose path ends with `Baloo2-SemiBold.ttf`. This is the **primary non-vacuous mechanical guard** for Gap 2 — it depends on no global state, no ordering and no exception plumbing, and it fails deterministically if the file is renamed, moved, or dropped from the `assets:` list, which is the realistic regression. The load test above is the stronger claim but the more fragile observation; treat this one as the floor beneath it, not as a secondary nicety.

    Third test — fetching is off. Call `configureFonts()` and assert `GoogleFonts.config.allowRuntimeFetching` is `false`.

    Fourth test — the UI-SPEC typography contract still holds. This test pumps the app and therefore resolves the family, which is exactly why it must come last. Build `EnglishReflexApp`'s theme (pump the app widget and read `Theme.of(context)` from a `Builder`, or construct the same `ThemeData` the widget builds) and assert: `displayLarge` has `fontSize` 32, `fontWeight` `FontWeight.w600`, `height` 1.3 and a `fontFamily` containing `Baloo2`; `headlineSmall` has `fontSize` 24, `fontWeight` `FontWeight.w600`, `height` 1.2 and a `fontFamily` containing `Baloo2`; `labelLarge` has `fontSize` 18 and a `fontFamily` that does not contain `Baloo2`; `bodyLarge` has `fontSize` 16 and a `fontFamily` that does not contain `Baloo2`. Note in a comment that `google_fonts` returns a family string of the form family-underscore-variant with the bare family as a fallback, which is why the assertion is a `contains` rather than an equality.

    In `.claude/CLAUDE.md`, update the existing `google_fonts` row in the Supporting Libraries table so it records that the Baloo 2 SemiBold instance is bundled under `assets/fonts/` and that `GoogleFonts.config.allowRuntimeFetching` is disabled, making the app's font loading fully offline and keeping the release build free of any network permission.
