## Spacing Scale

Declared values (must be multiples of 4), used as Flutter logical-pixel (dp) values:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, tight inline padding |
| sm | 8px | Compact spacing (mascot face features, badge padding) |
| md | 16px | Default element spacing, screen edge padding |
| lg | 24px | Section padding (question card padding, list item padding) |
| xl | 32px | Layout gaps (space between mascot and question text) |
| 2xl | 48px | Major section breaks (space above/below the Stop button) |
| 3xl | 64px | Page-level spacing (top padding on recording screen above mascot) |

Exceptions (large-touch-target requirement per D-14 "big friendly buttons/touch targets" and UI-01):
- **Stop button (record control):** 96px diameter circular button — exceeds standard 44px minimum touch target deliberately; this is the single most important tap target on the recording screen (LOOP-05: "large, always-visible stop button").
- **History list row:** 64px minimum height (not on the 4px content scale but a touch-target floor) to keep rows easily tappable at arm's length.
- **Mascot icon:** 120px square in its idle/recording states — sized as a visual anchor, not a tap target.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | Regular (400) | 1.5 |
| Label | 18px | SemiBold (600) | 1.2 |
| Heading | 24px | SemiBold (600) | 1.2 |
| Display | 32px | SemiBold (600) | 1.3 |

Font-family mapping (only 2 weights total, per contract):
- **Display** (the question prompt text — the single most important readable-at-arm's-length element, UI-01) — `Baloo 2`, 32px, SemiBold, line-height 1.3.
- **Heading** (screen titles: "Exercise History", session detail title) — `Baloo 2`, 24px, SemiBold, line-height 1.2.
- **Label** (button text — e.g. Stop button label, history row action affordance) — default Material font, 18px, SemiBold, line-height 1.2.
- **Body** (history list metadata: date/time stamps, secondary text) — default Material font, 16px, Regular, line-height 1.5.

All sizes must respect the OS text-scale accessibility setting (do not hardcode `textScaleFactor: 1.0`) — large-readable-text is a named requirement (UI-01), so the app should scale up gracefully rather than clip.

## Color

Warm coral/orange/yellow palette (D-12), Duolingo-style saturated-but-friendly (D-14):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFF8F0` (warm ivory) | Screen background on both Recording and History screens |
| Secondary (30%) | `#FFDDB3` (soft peach) | Question card surface, history list row cards, mascot container background |
| Accent (10%) | `#FF6B35` (vibrant coral-orange) | Stop button fill, recording-active pulse ring around mascot, primary icon color in the app bar, session-detail play button |
| Destructive/Error | `#E5484D` (warm red, not clinical/pure red) | Error banner text/icon only (e.g. mic permission denied, save failure) — no true destructive (delete) action exists in Phase 1 |

Accent (`#FF6B35`) reserved for: the Stop button, the recording-active pulse/ring animation around the mascot, the play-icon on history rows and session-detail rows, and the app bar's primary icon (if any). Never used for plain body text, card backgrounds, or decorative fills — accent must always mark something tappable or actively happening.

Text-on-color: use `#3D2B1F` (warm dark brown, not pure black) for body/heading text on the ivory/peach surfaces — softer than `#000000`, stays in the warm palette family while maintaining WCAG AA contrast against both `#FFF8F0` and `#FFDDB3`.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"STOP"** — the Stop button label (LOOP-05). Short, all-caps, matches the large circular touch-target aesthetic. Paired with a stop-square icon for redundancy. No "Start" button exists in this phase (D-01: recording starts automatically). |
| Empty state heading | **"No recordings yet"** — shown on the History list when zero sessions exist |
| Empty state body | **"Finish your first answer and it'll show up here."** — tells the user exactly what unlocks the list |
| Error state | **"Recording failed — check your microphone permission and try again."** — used for mic-permission-denied or save-failure cases; names the likely cause (permission) and the next action (retry) rather than a generic "Something went wrong" |
| Destructive confirmation | Not applicable in Phase 1 — no delete/edit action exists yet (history is append-only per D-05/PERSIST-01). If a future phase adds delete, reserve the Destructive/Error red (`#E5484D`) and a confirm dialog at that time. |

Additional in-flow copy (discretion, consistent with locked direction):
- Auto-replay indicator (while the just-recorded answer plays back per D-10): small label under the mascot, **"Playing your answer…"**
- Reset-to-next-question transition (D-03, no button, automatic): no copy needed — the new question text itself is the signal.
- History session-detail screen title: **"Session — {date, time}"** (e.g. "Session — Aug 7, 2:45 PM").

## UI Considerations

Applicable state considerations resolved: 5 covered, 2 backstop, 1 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | History list (zero sessions) | ✅ covered | Empty History renders "No recordings yet" / "Finish your first answer and it'll show up here." copy (see Copywriting Contract) |
| loading | Mic permission request on first launch | 🧪 backstop | Brief system-permission-dialog wait before recording can auto-start; no custom loading UI beyond the OS dialog itself — verify no blank/frozen screen appears while awaiting the permission callback |
| error | Mic permission denied / recording save failure | ✅ covered | Error banner shows "Recording failed — check your microphone permission and try again." copy (see Copywriting Contract); question screen stays visible so the user isn't stuck |
| populated | History list with sessions | ✅ covered | Each row shows session date/time + accent-colored play affordance at 64px min row height; tapping opens session detail (per D-06) |
| zero-one-many | Session detail question list | ✅ covered | Phase 1 sessions always contain exactly 1 `question_answers` row (D-05); detail view renders a single-item list using the same row component Phase 2 will reuse for many rows — no restructuring needed later |
| long-text | Question display text (hardcoded rotating list, D-02) | 🧪 backstop | Question text wraps across multiple lines at 32px Display size with no truncation; verify no overflow/clipping on the longest hardcoded question string at the largest supported OS text-scale setting |
| overflow | Auto-stop-at-60s vs. manual Stop tap race (D-09) | ⚠ unresolved | No explicit UI treatment specified for the exact frame where auto-stop fires simultaneously with a manual Stop tap; planner should treat the resulting visual state as identical to a normal manual stop (assumption — first stop signal wins, second is a no-op) |
| populated | Recording-active state (mascot + Stop button) | ✅ covered | Mascot shows a "listening" face variant with an accent-colored pulse ring while recording; Stop button is the only visible control (D-04 — no elapsed timer/countdown UI in this phase) |
