<objective>
Deliver the phase's tracer: a real, configured practice session that runs one question end
to end - Setup screen (topics + gated START SESSION) → practice screen carrying a
SessionConfig → 3-2-1 get-ready countdown → per-question `t` countdown → arming → recording
with a `d` deadline and readout → one durable committed answer → completion state.

Purpose: prove the whole Phase 2 architecture (config transport, the one timing primitive,
the extended phase machine, the promoted write path, the new entry point) on one thin path
before any horizontal expansion. Every layer this phase touches is wired here, for keeps -
this is production code, not a prototype. Task 2 then promotes the crash-safety write path
from "a session IS one answer" to "a session is N answers", which is the identity-model
transition the rest of the phase builds on.

Output: `SessionConfig`, `PausableCountdown`, `SetupScreen`, three new `PracticePhase`
values with keyed controls, a configurable-and-observable `d` deadline, and the single
promoted `DatabaseHelper.appendAnswer` write path.
</objective>

<assumption_delta_decision>
The assumption-delta detector fired on this phase with a **pluralization** signal
("across multiple questions"). Recorded verbatim, and implemented by Task 2:

- **Noun now primary:** a **session** is a container of **N** answers. Phase 1's implicit
  "a session IS one answer" is the demoted special case.
- **Decision: `promote`.** `DatabaseHelper.insertAnsweredSession({questionText,
  audioRelativePath})` - which creates a session and its single answer in one transaction -
  encodes the singular assumption. The general representation is promoted:
  `Future<int> appendAnswer({int? sessionId, required String questionText, required String
  audioRelativePath})` becomes the ONE primary write path (D-26). It creates the `sessions`
  row lazily when `sessionId` is null and appends to it thereafter, each call in its own
  transaction. `insertAnsweredSession` survives ONLY as a one-line delegation to
  `appendAnswer(sessionId: null, …)` - it is expressed in terms of the general path, never a
  second independent writer of the same crash-safety-critical invariant.
- **Constraint that does not move:** the write ORDERING is untouchable - finalize the audio
  file on disk → ONE transaction → only then replay/advance. The `_disposed` check sits
  deliberately AFTER the DB commit (`lib/state/practice_state.dart:229-235` and `:254-277`).
- **Companion invariant test (Task 2):** a session with N answers round-trips - N rows are
  readable in insertion order, and a simulated process kill after answer k leaves exactly k
  answers under exactly one session row.
</assumption_delta_decision>
