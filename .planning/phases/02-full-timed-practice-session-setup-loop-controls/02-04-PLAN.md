<objective>
Make Pause a true pause. One `pause()` on `PracticeState` freezes the microphone, the single
live `PausableCountdown` and any replay-completion wait together; one `resume()` continues all
of them from exactly where they stopped. The session app bar gains the Pause/Resume action,
present in every phase and disabled where there is no clock to freeze.

Purpose: CTRL-04 is the phase's hardest requirement because four separate clocks must freeze
in lock-step, and because `record`'s `pause()` fails SILENTLY in the wrong state - a
non-throwing call is not proof the microphone stopped. Getting this wrong produces a UI that
says "nothing is being recorded" over a live microphone, which is the worst honesty failure
available in this phase.

Output: confirmed pause/resume across the recorder, the player and every countdown, with the
`d`-derived pausable replay timeout that replaces the fixed 65-second one.
</objective>

`lib/services/recording_service.dart`: add `Future<void> pause()`, `Future<void> resume()`,
`Future<bool> isPaused()` and `Stream<bool> get onPausedChanged` to the `RecorderBackend`
abstract class. Keep the seam free of `package:record` types - map `RecordState` to a bool
inside `_RecordPackageBackend` only: `onPausedChanged` filters out `RecordState.stop` and maps
`RecordState.pause` to true. Document on the stream that it is the ONLY way Dart learns about
a pause the app did not request (an answered call on iOS, audio-focus loss on Android), which
is what plan 02-05 subscribes to.

Add `Future<bool> pause()` and `Future<bool> resume()` to `RecordingService` itself. Both
return whether the microphone state ACTUALLY changed. `pause()` returns false immediately when
not recording; otherwise it awaits the backend pause and then awaits `isPaused()`, and only
freezes the deadline countdown and returns true if that confirms. `resume()` mirrors it. The
doc comment must state the mechanism, not just the rule: `record`'s pause is a guarded
early-return on both platforms - iOS guards on the recorder being in the record state, Android
on `isRecording()` - so a call that lands in the wrong state returns normally having done
nothing, and a caller that infers "the mic is paused" from "the call did not throw" publishes a
banner over a live microphone. Because pause EXCISES the paused span from the audio file, a
deadline that keeps running would also cut the answer short by the paused duration - so the
deadline must freeze in lock-step or not at all.

`lib/services/audio_player_service.dart`: add `Future<void> pause()` and `Future<void> resume()`
to `AudioPlaybackBackend` and to `AudioPlayerService`. Add a top-level
`Duration replayCompletionTimeoutFor(Duration answerLimit) => answerLimit + const
Duration(seconds: 5);` carrying the "+5s slack" rationale in one place, and add an optional
`Duration? completionTimeout` parameter to `play(...)` defaulting to the existing
`kReplayCompletionTimeout` constant so every current test passes unchanged. Replace
`completed.timeout(...)` with a `Completer` resolved by EITHER the completion subscription OR a
