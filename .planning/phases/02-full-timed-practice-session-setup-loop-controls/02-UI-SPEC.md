# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This phase EXTENDS the Phase 1 design system — it does not replace it.** Every token below is
already implemented in `lib/main.dart` (`EnglishReflexApp` colour constants + `ThemeData.textTheme`).
Phase 2 introduces **zero new base tokens**: no new palette entry, no second font family, no new
font-size scale step. The only additions are two *derived* geometry values (a 4× Display glyph for
the 3·2·1 numeral and a 96px countdown ring), both listed as explicit exceptions with rationale.

Upstream sources: `02-CONTEXT.md` (D-16..D-31, locked), `01-UI-SPEC.md` (locked design system),
`01-CONTEXT.md` (D-01..D-15), `REQUIREMENTS.md` (SETUP-02..07, LOOP-01/02/07/08, CTRL-01..04, UI-01).

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Flutter project; shadcn and component registries are a web (React/Next/Vite) concept and are not applicable |
| Preset | not applicable |
| Component library | Flutter Material 3 (`ThemeData(useMaterial3: true)`), no third-party UI kit. Phase 2 uses stock `Slider`, `Switch`/`SwitchListTile`, `CheckboxListTile`, `ChoiceChip`, `AlertDialog`, `PopScope`, `CircularProgressIndicator` — all Material, all themed from `Theme.of(context)` |
| Icon library | Material Icons (stock default per CLAUDE.md — do not add a second icon package). The mascot stays the bespoke Flutter-primitive `Mascot` widget |
| Font | **Display/Heading:** `Baloo 2` (bundled `assets/fonts/Baloo2-SemiBold.ttf`, runtime fetching OFF). **Label/Body:** Flutter default Material font. Unchanged from Phase 1 |

**Design tokens are Dart, not CSS.** Every value below is a Flutter logical pixel (dp) expressed as
an `EdgeInsets`/`SizedBox`/`fontSize`, and every colour is read through
`Theme.of(context).colorScheme` — screens never hardcode a hex (established Phase 1 pattern,
enforced by convention in `01-UI-SPEC.md`).

**Package note (traceable to D-30):** `wakelock_plus` is added this phase. It has **no UI surface** —
no icon, no indicator, no user-visible affordance. It is held for the duration of an active session
and released on session end/dispose. The planner should record it in CLAUDE.md's Supporting
Libraries table with the D-30 rationale (the default OS screen timeout is frequently shorter than one
`t`+`d` cycle, so without it the screen locks mid-answer).

## Spacing Scale

Declared values (all multiples of 4), unchanged from Phase 1, used as Flutter logical-pixel (dp) values:

| Token | Value | Usage in Phase 2 |
|-------|-------|------------------|
| xs | 4px | Icon-to-label gaps, chip internal tightening |
| sm | 8px | Section-label → helper-text gap, readout → slider gap, banner icon → text gap |
| md | 16px | Default element spacing; STOP → `d` readout gap; footer vertical padding; banner padding |
| lg | 24px | Screen edge padding (both screens); card interior padding; card corner radius; numeral → caption gap |
| xl | 32px | Gap between Setup sections; anchor slot → focus slot gap on Practice |
| 2xl | 48px | Focus slot → control slot gap on Practice |
| 3xl | 64px | Reserved (page-level spacing); also the button-height floor below |

**Exceptions** (carried forward from Phase 1 unless marked NEW):

| Exception | Value | Why it is not on the 4px content scale |
|-----------|-------|-----------------------------------------|
| STOP circle | 96px diameter | The single most important tap target in the app (LOOP-05); deliberately far above the 44px floor. Unchanged |
| Primary button height | 64px | Touch-target floor for `START SESSION`, `RESUME`, `View this session`. Unchanged |
| Secondary text button | min 64×48 | Existing pattern (`_ErrorBanner` Retry, `history-error-retry`). Reused for `Keep going` / `Back to setup` |
| List row min height | 64px | Applies to topic checkbox rows and the replay toggle row, matching the Phase 1 history-row floor |
| Mascot | 120px face inside a 144px box | Visual anchor, not a tap target. Unchanged |
| **Countdown ring (NEW)** | 96px diameter, 8px stroke | Sits inside the same 144px anchor box the mascot occupies, so swapping mascot ↔ ring causes **zero layout shift** between `getReady`/`reading`/`recording`. Not a tap target |
| **Countdown numeral box (NEW)** | 160px tall | Fixed height for the 3·2·1 glyph so the focus slot does not jump when the numeral changes width (3 → 2 → 1) |
| App-bar icon buttons | 48px | Material `IconButton` default; above the 44px floor |

**44px touch-target floor holds for every interactive element in this phase.** The Material `Slider`
default hit area (48px tall) and `IconButton` (48px) both clear it without customisation; topic rows
and the toggle row are pinned to 64px explicitly.

**Phase 2 role assignments:**

| Element | Role |
|---------|------|
| Question prompt text (unchanged) | Display |
| Setup numeric readouts (`10`, `5 sec`, `60 sec`) | Display |
| Completion headline ("Nice work!") | Display |
| App bar titles ("EnglishReflex", "Question 3 of 10", "Session complete") | Heading |

| `t`-countdown numeral inside the ring | Heading |
| Setup section labels ("Topics", "Level", "Questions", "Thinking time", "Answer length") | Label |

| Paused banner text | Label |
| Setup helper text, phase captions, the `d` remaining readout, completion sub-line, dialog body, error copy | Body |

**Documented exception — the 3·2·1 glyph (NEW).** The full-screen countdown numeral renders at
**128px (Display × 4), SemiBold, Baloo 2, coral** — a single glyph, not a text size. It is **not a
fifth scale step**: nothing else in the app may use 128px, and it must be authored as
`textTheme.displayLarge!.copyWith(fontSize: 128, color: accent)` so it stays derived from the one
Display token. It is wrapped in `FittedBox(fit: BoxFit.scaleDown)` inside the 160px box — the exact
pattern the 96px STOP button already uses for its label, so it scales *down* rather than overflowing
at the largest OS text-scale setting.

**`textScaler` is never pinned (UI-01).** `MaterialApp` still has no `builder:` MediaQuery override.
Every Phase 2 surface must survive the largest OS text-scale setting by **scrolling or wrapping, never
clipping**:
- Setup body is a `SingleChildScrollView`; the Start footer is pinned outside it.
- The practice screen keeps Phase 1's `LayoutBuilder` + `SingleChildScrollView` + `ConstrainedBox`
  pattern for all phases including the countdowns and the completion state.
- App-bar titles use `overflow: TextOverflow.ellipsis` (a truncated "Question 100 of 100" is
  acceptable; a RenderFlex overflow is not).
- Fixed-size targets (96px STOP circle, 160px numeral box, 96px ring) contain their text with
  `FittedBox(scaleDown)`.

## Color

Unchanged from Phase 1. All four values are already `static const Color` fields on `EnglishReflexApp`:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFF8F0` warm ivory | Screen background on Setup and Practice; the Start footer background; the dialog surface |
| Secondary (30%) | `#FFDDB3` soft peach | Question card, topics card, app bar, unselected CEFR chips, slider inactive track, countdown-ring track, paused banner, error banner, history rows |
| Accent (10%) | `#FF6B35` coral-orange | See reserved-for list below |
| Destructive/Error | `#E5484D` warm red | Error banner icon + text + Retry label (unchanged); the `End session` dialog action **label only** |

Text on ivory/peach: `#3D2B1F` warm dark brown. Brown-on-coral is 4.7:1 (`onPrimary` is deliberately
brown, not white — see the comment in `lib/main.dart`), so coral-filled controls keep AA-legible labels.

**Accent (`#FF6B35`) reserved for — explicit list:**

1. The `STOP` circle (recording).
2. The `RESUME` pill (paused).
3. The `START SESSION` button (Setup, enabled state only).
4. The `View this session` button (completion state).
5. The **selected** CEFR chip fill.
6. The **checked** topic checkbox fill.
7. The `Slider` active track and thumb (all three numeric settings).
8. The replay `Switch` active track/thumb.
9. App-bar action icons (History on Setup; Pause/Resume and Stop during a session) — via the existing
   `appBarTheme.actionsIconTheme`.
10. The 3·2·1 countdown numeral.
11. The countdown-ring **elapsed arc** (the ring's remaining track is peach).
12. The recording pulse ring around the mascot (unchanged from Phase 1).
13. The paused-banner pause icon.

**Never** used for: body text, headings, card fills, section backgrounds, decorative shapes, the `d`
remaining-seconds readout, or any disabled control. Accent must always mark something **tappable or
actively happening**.

**Phase 2 colour discipline rules (auditable):**

- **At most one large coral surface per screen.** Setup: the `START SESSION` button. Practice: the
  `STOP` circle (or, in its place, the `RESUME` pill or the `View this session` button — never two at
  once). Every other coral element must be ≤ a 48px control, a ≤ 8px stroke, or a single glyph.
- **Peach never sits on peach.** The CEFR chip row, the three sliders and the replay toggle sit
  directly on the **ivory** background, *not* inside peach cards — otherwise unselected peach chips
  and peach inactive tracks would vanish into their container.
- **Peach marks content, never form chrome.** Phase 1 used peach for the question card and history
  rows (data surfaces). Phase 2 therefore gives the **topics list** a peach card (it is question-bank
  data, and becomes Firestore-backed in Phase 3) and leaves the numeric/level/toggle controls bare on
  ivory. This is what keeps ivory dominant at ~60% on a control-dense Setup screen.
- **Disabled controls use no accent and no error red.** The disabled `START SESSION` uses a peach
  (`#FFDDB3`) fill with a **full-opacity** brown label — deliberately still readable rather than a
  greyed ghost, because it is always paired with the reason ("Pick at least one topic to start."). A
  disabled Pause action renders as brown at 38% opacity, never coral.
- **Error red is never a fill.** Carried forward verbatim from Phase 1: `#E5484D` colours icons,
  text and text-button labels only.

### Practice screen — the three-slot model

The practice screen keeps Phase 1's vertical rhythm and fills three slots in a constant order. Slot
identity is what makes the two countdown kinds unmistakable (D-22):

```
AppBar [ "Question 3 of 10" .......... (pause, coral) (stop, coral) ]
  ↳ no History icon (D-29), no back arrow (automaticallyImplyLeading: false)
────────────────────────────────────────────────────────────────────
[ paused banner ]   ← docked here when paused, same slot/construction
[ error banner ]      as the Phase 1 error banner (never instead of
                      the content — always above it)
────────────────────────────────────────────────────────────────────
  ANCHOR SLOT   144px box     mascot  |  countdown ring
       ↓ 32px (xl)
  FOCUS SLOT                  question card  |  3·2·1 numeral  |  completion headline
       ↓ 48px (2xl)
  CONTROL SLOT  PhaseControl  STOP+readout | RESUME | caption | completion buttons | ∅
```

| Phase | Anchor slot | Focus slot | Control slot |
|-------|-------------|------------|--------------|
| `getReady` (3·2·1, LOOP-01 / LOOP-07) | Mascot, resting face, **no** pulse ring | **128px coral numeral** in a 160px box — question card HIDDEN (D-22) | Caption: "Get ready…" (session start) / "Next question…" (between questions) |
| `reading` (`t` countdown, LOOP-02) | **96px countdown ring**, coral elapsed arc on peach track, remaining seconds at Heading 24 inside | Question card, peach, VISIBLE and dominant (D-22) | Caption: "Speak when the timer hits 0" |
| `arming` (D-20) | Mascot, resting face, no pulse ring | Question card | Caption: "Getting ready…" |
| `recording` | Mascot, listening face + coral pulse ring | Question card | `STOP` 96px circle → 16px → "{M}:{SS} left" (Body 16, brown) |
| `saving` | Mascot, resting | Question card | Caption: "Saving your answer…" |
| `replaying` | Mascot, resting | Question card | Caption: "Playing your answer…" |
| `paused` | Mascot, resting, **pulse ring OFF** | Whatever the underlying phase showed, **frozen** (question card, or the countdown numeral stopped on its current digit) | `RESUME` pill: `FilledButton`, 64px height, coral, play icon + Label |
| `complete` | Mascot, resting | "Nice work!" (Display) + "{N} answers recorded." (Body) — question card HIDDEN | `View this session` (coral, full width, 64px) → 8px → `Back to setup` (TextButton, brown, min 64×48) |
| `error` | Mascot, concerned face | Question card (stays visible so the user is never on a dead-end blank screen — Phase 1 contract) | Empty keyed `SizedBox.shrink`; the error banner owns Retry |
| `idle` | Mascot, resting | Question card | "Try again" — unchanged from Phase 1 |

**Why the two countdowns can never be confused.** They occupy *opposite* slots:

|  | 3-second countdown | `t` countdown |
|--|--------------------|---------------|
| Numeral | 128px, coral, in the **focus** slot (literally where the question would be) | 24px, brown, in the **anchor** slot inside a ring |
| Question | Hidden | Visible, dominant |
| Mascot | Present | Replaced by the ring |
| Meaning | "Nothing to read yet — get ready" | "Read this now — you speak at 0" |

Because the ring is 96px inside the same 144px box the mascot occupies, and the numeral box is a
fixed 160px, **no slot changes height between phases** — there is no layout jump anywhere in the loop.

**`STOP` stays dominant while recording (D-21).** The remaining-seconds readout is Body 16/400 in warm
brown on ivory, 16px below a 96px coral circle. It is deliberately **not** coral (that would create a
second focal point), has **no** colour change or animation in its final seconds (any red/coral
threshold treatment would break the accent and error-colour contracts), and is **not** a
`liveRegion` for screen readers (a per-second announcement would be noise while the user is speaking).

## Interaction Contract

### Session app bar (CTRL-01/02, D-29)

- Title: `"Question {k} of {N}"` at Heading with `overflow: TextOverflow.ellipsis`. **This is the
  phase's only progress indicator** — a separate linear progress bar was considered and rejected: the
  title is visible in every phase including both countdowns, and a non-tappable coral bar would dilute
  the accent budget for no added information.
- `k` increments **at the start of the inter-question `getReady` countdown**, so the counter always
  names the question the user is about to face. At session start the title reads "Question 1 of {N}".
- Actions, left→right: Pause/Resume, then Stop. Both are 48px `IconButton`s, coral via the existing
  `appBarTheme.actionsIconTheme`. Icons: `Icons.pause_rounded` / `Icons.play_arrow_rounded` /
  `Icons.stop_rounded`.
- **No History icon** (D-29) and **no back arrow** (`automaticallyImplyLeading: false`).
- Stop is coral, **not** error red. Ending a session early destroys nothing — every answer is already
  durably saved (PERSIST-01) — so the destructive palette would overstate it. Error red appears only
  on the confirmation dialog's `End session` label.

**Action availability per phase.** Pause is *present at all times* during a session (CTRL-01 read
literally) but inert where there is no clock to freeze — it is disabled, never hidden, so it can never
appear to have vanished:

| Phase | Pause/Resume | Stop |
|-------|--------------|------|
| `getReady` | enabled — freezes the 3·2·1 | enabled |
| `reading` | enabled — freezes the `t` countdown | enabled |
| `arming` | disabled (the recorder start is in flight) | enabled |
| `recording` | enabled — `record.pause()`, freezes the `d` deadline | enabled |
| `saving` | disabled (strictly transient, sub-second) | enabled |
| `replaying` | enabled — pauses playback, resumes it in place | enabled |
| `paused` | enabled (shows Resume) | enabled |
| `error` | disabled | enabled |
| `idle` | disabled | enabled |
| `complete` | **hidden** — the session is over | **hidden** |

**Implementation flag for the planner:** enabling Pause during `replaying` means
`AudioPlaybackBackend` needs `pause()`/`resume()`, and the playback completion timeout currently
derived from `kMaxRecordingDuration` must **exclude paused time** — otherwise a long pause during
replay trips the timeout and the loop advances behind the user's back.

### Pause (CTRL-04 / D-24)

- Resume continues from exactly where it stopped; it never restarts the current step.
- The paused banner is docked under the app bar in the same slot and with the same construction as the
  Phase 1 error banner: peach `Container`, full width, 16px padding, `Icons.pause_rounded` in coral,
  8px gap, text at Label 18/600 brown, wrapped in `Expanded` so it wraps rather than overflows.
- **The mascot's pulse ring must be off in every paused state.** The pulse ring means "the mic is
  live"; leaving it running while paused would be the single worst honesty failure in this phase.
- The frozen numeral/readout stays on screen at its frozen value — a frozen number plus the banner is
  unambiguous in a way that hiding either one would not be.

### Stop with confirmation (CTRL-03 / D-25 / D-29)

- Widget: Material `AlertDialog` on the ivory surface, Heading title, Body content, 24px radius.
- The session **auto-pauses while the dialog is open** and resumes on cancel (D-25).
- `barrierDismissible: true` — a barrier tap returns `null` and is treated **identically to
  "Keep going"** (resume). There is exactly one destructive path and it always requires the explicit
  `End session` tap.
- System Back / back gesture is intercepted with `PopScope` and routed into this same dialog (D-29),
  so there is exactly one way to end a session early.
- On confirm: with ≥ 1 answer captured → the completion state (D-27). With 0 answers → pop straight
  back to Setup with no completion screen, because there is nothing to view and nothing was written
  (D-26).
- `PopScope` interception is **released** in the `complete` phase, where the back arrow reappears and
  pops to Setup.

### `PracticePhase` and the `kPhaseControlKeys` totality contract

`lib/widgets/phase_control.dart` holds a deliberately **total** map from `PracticePhase` to a widget
key, proven by `test/widgets/phase_control_test.dart`
(`kPhaseControlKeys.length == PracticePhase.values.length`, and every phase renders exactly one keyed
widget). **Adding a phase without adding an entry fails that test by design** — that failure is the
guardrail, not an obstacle. Phase 2 must therefore:

**If the loop is modelled with new `PracticePhase` values** (recommended names — the planner may
rename, the obligations do not change):

| New phase | Key | Keyed widget |
|-----------|-----|--------------|
| `getReady` | `practice-control-get-ready` | The caption ("Get ready…" / "Next question…") |
| `reading` | `practice-control-reading` | The caption ("Speak when the timer hits 0") |
| `paused` | `practice-control-paused` | The `RESUME` pill |
| `complete` | `practice-control-complete` | A `Column` holding `View this session` + `Back to setup` |

Existing entries (`idle`, `arming`, `recording`, `saving`, `replaying`, `error`) keep their keys. The
`recording` entry's keyed widget becomes a `Column` containing the 96px STOP circle **and** the `d`
readout — still exactly one keyed widget, so the existing assertion holds unchanged.
`PhaseControl` gains a `remainingSeconds` input for that readout.

**If pause is instead modelled as an orthogonal `bool isPaused` flag** (leaving `phase` intact
underneath, which is the cleaner state model), then `PhaseControl` must **short-circuit to the keyed
`RESUME` control before the phase switch**, and `phase_control_test.dart` must be extended with an
`isPaused == true` case. Either modelling is acceptable; what is **not** acceptable is a reachable
screen state with no keyed control, because that is a screen the user cannot leave.

**New reasoning the existing doc comment does not yet cover.** `PhaseControl`'s comment currently
justifies status-label-only controls with "every `await` in `stopRecording()` is guarded, so these
phases are strictly transient." That argument does **not** transfer to `getReady` and `reading`, which
are **timer-driven**, not await-driven. Their justification is different and must be written into the
comment: they are bounded by a timer that always fires, **and** the app bar carries Pause and Stop in
both phases (CTRL-01/02), so neither is ever a dead end even if a timer were lost. If a future change
removes the app-bar controls from those phases, their captions must be upgraded to real affordances.

### Loop behaviour notes with UI consequences

- **D-20 arming window:** the `t` countdown runs fully to zero, and only then does the recorder arm.
  The user therefore sees `reading` → `arming` ("Getting ready…") → `recording`. The STOP button and
  the listening mascot never appear while the mic is cold.
- **D-23 cycling:** when `question_count` exceeds the placeholder bank, questions repeat. There is
  **no** "seen before" badge or marker — it would be visual noise and would leak an implementation
  detail that disappears in Phase 3. Repeats in a session-detail list are expected and unlabelled.
- **D-31 interruption:** the app returns to the foreground already in the paused state showing the
  interruption banner variant. The app **never** silently resumes recording; resuming is always an
  explicit tap.
- **D-30 wakelock:** no UI surface at all.
