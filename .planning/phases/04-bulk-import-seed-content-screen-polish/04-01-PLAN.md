     would go to the server and come back as an opaque failure with nothing naming the real
     cause. That is why this constant and the chunking below exist rather than trusting the
     SDK. State plainly that the number itself is the documented server limit and has not
     been observed failing at 501 in this project; the 600-row seed import in plan 04-05 is
     what exercises the multi-chunk path against the real backend.

       clock can place an import before existing questions in bank order.

       cumulative committed count ONLY after a commit future has completed — never
       optimistically per row. If a commit fails: log it, and if NO earlier chunk committed
