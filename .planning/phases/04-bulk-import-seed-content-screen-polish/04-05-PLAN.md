  <instructions>
This is the phase's central act: seeding the bank and proving the importer are the same thing
(D-57). There is no CLI that can drive the OS document picker, so these steps need a real
device and a real hand.

**Setup**
1. Copy `seed/seed-questions.json` onto the test device — `adb push seed/seed-questions.json /sdcard/Download/` on Android, or AirDrop / the Files app on iOS.
2. Install and launch the app on the device with a working network connection.

**A. Seed the bank (IMPORT-05, IMPORT-01)**
3. Setup should show the no-topics empty state, since the collection is empty. Confirm it says the bank is empty rather than showing a could-not-load failure.
4. Tap the import action in the AppBar (the upward-arrow file icon, left of the history icon). Confirm the sheet opens on its idle state showing the expected JSON shape, and that no route was pushed — the Setup screen is still visible behind the sheet's scrim.
5. Tap "Choose a JSON file", pick `seed-questions.json`, and watch the states go by: "Checking your file…", then "Comparing with your bank…", then the saving caption with a determinate bar. **Confirm the bar advances in more than one visible step** — 600 rows exceed one write batch, so this is the multi-chunk commit path running against the real backend.
6. Confirm the result reads "600 questions added" with no duplicates line and no skipped line.
7. Tap Done. Confirm the topic list on Setup now shows all ten topics **without leaving and returning to Setup** — that is the sheet-dismiss refresh (D-51).

**B. Re-importing is harmless (IMPORT-04, D-54)**
8. Import the same file again. Confirm the result reads "No questions added" and "600 were already in your bank", with no skipped rows and no error treatment anywhere on the surface.

**C. Every combination returns questions (IMPORT-05)**
9. Spot-check at least six topic-by-level combinations spread across different topics and different levels — including at least one A1 and one C2 — and confirm each starts a session rather than showing a no-questions message.
10. Confirm bank order: within one topic and level, the first questions of the session appear in the same order as that cell in `seed/seed-questions.json` (D-63).

**D. Per-row reporting (IMPORT-04)**
11. Build a small deliberately-broken file on the device: take five rows from the seed, change one row's level to something outside A1–C2, blank one row's content, replace one row with a value that is not an object, and leave two valid. Import it.
12. Confirm the result names two added, and lists each of the three skipped rows by its position in the file with a reason, and that the row with the bad level quotes the offending value back.

**E. The failure surfaces (IMPORT-04, D-60, D-62)**
13. Import a file that is not JSON at all. Confirm the file-problem state with the message about opening the file, and NO expected-shape block.
14. Import a valid JSON file that has no `data` key. Confirm the file-problem state WITH the expected-shape block.
15. Import a file whose `data` list is empty. Confirm the empty-file message, with no error icon and no red.
16. Turn the network off entirely, then import a valid file. Confirm the import stops at the bank-comparison step and shows the unreachable message stating that nothing was imported. Turn the network back on and tap "Try again" — confirm it resumes **without** re-opening the file picker.

**F. The write cannot be walked out of (IMPORT-04)**
17. Start an import of the full 600-row file and, while the saving bar is on screen, try to dismiss the sheet three ways: drag it down, tap outside it, and use the system back gesture. Confirm all three are refused. **Record which mechanism shipped** — the pop-scope guard alone, or the non-dismissible fallback plan 04-02 sanctioned.
18. Start the 600-row import again and background the app while the bar is on screen; return after a few seconds. Confirm the sheet is still there and still shows an outcome. **This is the one interaction race the UI-SPEC left unresolved** — record exactly what happened.

**G. The 30-topic limit (D-61)**
19. This needs more than 30 distinct subjects, which the ten-topic seed does not provide. Import a small file inventing 25 additional one-question subjects, then select 31 or more topics on Setup and tap Start. Confirm the message names the 30-topic limit and tells the user to uncheck a few — and does NOT mention the connection. Confirm every topic, the level and all three slider values survive.
20. Delete those 25 throwaway subjects from the Firebase console afterwards, or note them for cleanup, so the shipped bank is back to the ten curated topics.

**H. Accessibility and layout (UI-01)**
21. Raise the OS text scale to its maximum and repeat steps 4, 6 and 12. Confirm: the Setup AppBar title ellipsises rather than overflowing with two actions present; the JSON shape example wraps legibly inside its peach card; each skip row's question text stays on exactly one ellipsised line while its reason line wraps freely; and the sheet scrolls so the primary button is always reachable.
22. Import a file containing one deliberately very long subject name, then confirm on Setup that its topic row grows and wraps rather than clipping at maximum text scale. Remove that subject afterwards.

Report the result of every lettered group, and quote the exact counts the app reported in
steps 6, 8 and 12.
